# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Proyecto

Sitio web de **CANCO STAR**, una marca de café de especialidad de Acevedo, Huila (Colombia). El repositorio tiene dos carpetas:

- `frontend/`: la página, una SPA en React 19 + Vite 8, en JavaScript (sin TypeScript). Todo el texto visible está en español, con traducciones (ver "Idiomas"). **Todas las rutas de la sección "Arquitectura" (`src/...`, `public/...`) son relativas a `frontend/`.**
- `backend/`: la API en PHP (Leaf MVC 4) para la base MySQL `canco`. Es una **copia** de `Desktop/api-canco`, que tiene su propio git con el historial anterior. Ver la sección "Backend".

## Comandos

```bash
cd frontend
npm run dev       # servidor de desarrollo de Vite
npm run build     # build de producción en frontend/dist/
npm run preview   # servir el build localmente
npm run lint      # ESLint (flat config: js recommended + react-hooks + react-refresh)
npm run traducciones  # dice qué falta traducir (o sobra) en en.js, pt.js y zh.js

cd backend
php leaf serve    # inicia la API (necesita composer install, .env y MySQL encendido)
```

No hay tests ni un framework de testing configurado.

## Arquitectura

- `src/main.jsx` envuelve `<App />` en `<BrowserRouter>` (react-router-dom v7), `<LanguageProvider>` y `<CartProvider>`. `App.jsx` tiene un estado `splash` (`"visible"` → `"leaving"` → `"gone"`): primero renderiza `SplashScreen`; al hacer clic muestra `AnnouncementBar` → `Head` → `<Routes>` → `Footer` debajo, mientras el splash se desvanece encima (clase `fade-out`), y lo quita a los `SPLASH_FADE_MS` (800 ms, que deben coincidir con la `transition` de `.splash-screen`). El texto del splash se va en 0,35 s para no cruzarse con el título del inicio.
- **Splash:** tiene dos capas. `::before` es la foto: `Paradise.png` en pantallas horizontales e `inicio pantalla.jpeg` en verticales (`@media (orientation: portrait)`), un poco desaturada y oscurecida. `::after` es la iluminación: el mismo brillo verde azulado de arriba que tiene el `body` y un degradado que termina en `--canco-negro` abajo. El título ("Canco Café"), la letra y el botón dorado (`.btn-gold`) son los mismos del hero, para que el paso no se note. Para una foto más nítida en computador, hace falta una horizontal de al menos 1920 px de ancho. La barra de anuncios, el header y el footer son compartidos por todas las páginas. `CartDrawer` y `ScrollToHash` van fuera de ese bloque. El contenido se oculta con `display: none` (no se desmonta), así que el video del reel empieza a cargar desde el principio.
- **Páginas:** van en `src/view/<pagina>/index.jsx` (export default) y se registran en `<Routes>` de `App.jsx`. Existen `/` (`view/home`, que renderiza `components/contents.jsx`) y `/tienda` (`view/tienda`).
- **Tienda:** los productos salen de `src/data/productos.js` (`categorias` y `productos`), no de la API. Los filtros viven en la URL: `?categoria=grano|molido|metodos|accesorios` y `?buscar=<texto>` (la búsqueda ignora tildes y mayúsculas). Así el mega menú (Parte 2) puede enlazar directo a `/tienda?categoria=metodos`, y cada tarjeta tiene `id={producto.id}`. `components/ProductCard.jsx` es la tarjeta: si el producto tiene `presentaciones` (250 g / 500 g), al elegir una cambian la foto y el precio. "Agregar" llama a `addItem` y abre el carrito. Un producto con `precio: null` muestra "Precio por confirmar" y un enlace a `/#contacto`.
- **Scroll al navegar:** `ScrollToHash` baja a la sección si hay `#id`, sube arriba al cambiar de página y **no se mueve** si solo cambian los parámetros de la misma página (los filtros de la tienda).
- **Header (rediseño por partes):** la Parte 1 está hecha: barra de anuncios, header fijo, búsqueda y carrito. Faltan la Parte 2 (mega menú en Tienda) y la Parte 3 (menú ☰ lateral para celular, con las categorías de Tienda en acordeón). Hasta la Parte 3, en celular los enlaces se muestran en una segunda fila.
  - `AnnouncementBar.jsx`: los mensajes salen del array `messages` y rotan cada 4 s (se pausan con el mouse encima). No es sticky: se va con el scroll.
  - Colores: la barra de anuncios es verde bosque (`#163f3d`) con texto dorado. El header usa su propio tono, `--canco-pizarra` (verde pizarra `#142626` translúcido al 82 %, con `backdrop-filter: blur`), y una línea dorada tenue abajo (`--canco-linea`); con `is-scrolled` pasa al 92 % de opacidad. Así no contrasta con el fondo oscuro de la página. Por pedido expreso, el header no debe repetir exactamente un color ya usado en otra parte. El texto va en crema y el dorado solo en detalles (línea bajo el enlace, contador del carrito).
  - `head.jsx`: es `position: sticky` y tiene 3 columnas en grid (logo → `/` | enlaces centrados | búsqueda y carrito). Recibe la clase `is-scrolled` (más sombra) cuando `scrollY > 40`. La búsqueda navega a `/tienda?buscar=<texto>`.
  - Como el header es fijo, `[id]` tiene `scroll-margin-top: var(--header-offset)`. Si cambia el alto del header, actualiza `--header-height` y `--header-offset` en `:root` (y en el breakpoint de 768px).
- **Carrito:** `context/cart.js` (contexto y hook `useCart`) y `context/CartProvider.jsx` (estado). Están en archivos separados para cumplir la regla `react-refresh/only-export-components`. Cada ítem es `{ id, nombre, presentacion, precio, imagen, cantidad }`; el `id` debe incluir la presentación (por ejemplo `grano-250g`). El carrito se guarda en `localStorage` (`canco-carrito`). `CartDrawer.jsx` es el panel lateral: usa `inert` cuando está cerrado, se cierra con Escape o con el fondo y devuelve el foco. Por ahora solo permite quitar productos (no cambiar la cantidad) y todavía no hay pago. `utils/format.js` → `formatPrice(37000)` da `"$ 37.000"`.
- **Fotos de productos:** están en `public/Products/`: `Canco250` y `Canco500` (las bolsas), `V60` (la cafetera), `Fv60` (los filtros de la V60), `PrensaF` y `Chemex`. Todas terminan en `.jpeg`, pero en realidad son PNG (las bolsas, unos 900 KB cada una), WebP o AVIF (`PrensaF`). Los navegadores las muestran igual, pero si alguna herramienta falla con ellas, esa es la causa.
- **Precios (confirmados en octubre de 2026):** café en grano y molido, $37.000 en 250 g y en 500 g; V60, $62.000; prensa francesa, $75.000; Chemex, $85.000 (estimado); filtros V60 (caja de 100), $30.000 (aproximado). La base MySQL `canco` de la API PHP (`backend/`) tiene precios viejos (250 g = $26.000), no tiene Chemex, filtros ni café molido, y todavía no hay endpoint de productos. Por eso la tienda usa `data/productos.js`.
- `src/components/` contiene los componentes reutilizables. Se exportan con nombre (`export function X`) y los nombres de archivo mezclan mayúsculas y minúsculas (`head.jsx`, `Cards.jsx`). Respeta el nombre exacto al importar, porque Vercel distingue mayúsculas y minúsculas y Windows no.
- **Navegación por secciones:** Inicio, Legado y tradición, Around The World y Contacto Star están en la página principal, una debajo de la otra. Los enlaces usan `<Link to="/#id">`, y `components/ScrollToHash.jsx` escucha la URL y baja con desplazamiento suave al `id`. Así funciona también desde otra página (por ejemplo, desde `/tienda`, `/#familia` vuelve al inicio y baja). Los ids son: `inicio` (hero), `reel`, `legado-y-tradicion` (sección de tarjetas), `procesos`/`familia`/`finca`/`paraiso` (el `slug` de cada tarjeta), `around-the-world`, `contacto-star` (footer), `contacto` y `redes`. Si cambias un id, actualiza `menuData` en `head.jsx` y los enlaces del footer.
- **Menú desplegable:** las opciones y subopciones salen del array `menuData` en `head.jsx`. Con mouse se abre al pasar por encima; en pantallas táctiles y con teclado, con el botón de flecha. Se cierra al hacer clic fuera o con Escape.
- **Estilos:** un único archivo global, `src/App.css`, con clases planas (sin CSS modules). Tiene un breakpoint `@media (max-width: 768px)`. Los colores de la marca, tomados del empaque, son variables en `:root`: `--canco-negro`, `--canco-carbon`, `--canco-teal`, `--canco-dorado`, `--canco-crema`, etc. Úsalas en lugar de escribir colores sueltos. Las animaciones respetan `prefers-reduced-motion`.
- **Tema oscuro en todo el sitio:** el fondo de la página es único y lo pone el `body`: `--canco-negro` con un brillo verde azulado arriba (`radial-gradient` con `background-attachment: fixed`). Las secciones (reel, Legado, Around The World, contenido de la tienda) **no tienen fondo propio**; no les pongas uno blanco ni claro. El texto general es `--canco-crema`. Sobre negro usa `--canco-teal-claro` para títulos y enlaces (el `--canco-teal` normal no se lee; resérvalo para fondos como botones activos o pestañas), `--canco-texto-suave` para descripciones y `--canco-borde` para bordes de botones y selectores. Las tarjetas y las ventanas usan `--canco-carbon` con borde `--canco-linea`, que pasa a dorado al pasar el mouse. Excepción: el área de la foto de los productos de la tienda es blanca, porque las fotos tienen fondo blanco. El hero y la cabecera de la tienda usan el mismo degradado (negro → `#163f3d` → `--canco-teal`), definido en un `::before` compartido (`.hero::before, .tienda-hero::before`) con un `mask-image` que lo desvanece hacia abajo para que se funda con el fondo de la página. Por eso esos dos bloques tienen más `padding` abajo. No le pongas `background` directo a `.hero` ni a `.tienda-hero`: volvería el corte recto. El footer es `--canco-carbon` con un brillo verde azulado desde abajo y una línea dorada arriba; sus títulos de columna van en dorado y en mayúsculas espaciadas, y sus enlaces en `--canco-texto-suave`, dorados al pasar el mouse.
- **Tipografía:** fuentes incluidas en el proyecto con `@fontsource-variable/montserrat` y `@fontsource-variable/inter`, importadas en `main.jsx` (no usan Google Fonts). `--fuente-titulos` (Montserrat) es para títulos, marca, menú, botones, etiquetas, precios y contadores; la lista de clases está en el bloque "TIPOGRAFÍA" al principio de `App.css`, así que **si creas un título o un botón nuevo, agrégalo ahí**. `--fuente-texto` (Inter) es la del `body`, para los párrafos. Las dos variables empiezan con `'Twemoji Country Flags'` para que las banderas se vean en Windows. El `body` tiene suavizado de fuentes y `line-height: 1.6`, pensados para texto claro sobre oscuro. Los títulos de sección (`.cards-section-title`, `.atw-title`) usan peso 400 y una línea dorada debajo (`::after`). La clase `.splash-screen.fade-out` está definida, pero ningún componente la usa.
- **Hero** (`contents.jsx`): es el `<h1>` del sitio, con un subtítulo y un botón dorado (`.btn-gold .hero-btn`) que lleva a `/#finca`, la tarjeta "La Finca". Se armó en capas según bocetos del equipo: "CANCO" arriba a la izquierda, papá en el centro-derecha y "ST★R" abajo a la derecha, con la estrella de Canco (el símbolo del logo, en dorado) en lugar de la "A".
  - **Dos cajas idénticas** (`.hero-frame`: misma posición, mismo tamaño y la proporción de la foto, `aspect-ratio: 1088/1600`). Atrás, `.hero-photo` lleva `.hero-bg` = `public/Campe_sino.jpeg` (`blur(1.5px)`, oscurecida; se pidió "no tan difuminado") más `::after` con el brillo verde azulado, y sus bordes se desvanecen hacia los lados. Adelante, `.hero-front` (sin máscara, para que las letras puedan salirse de la columna) lleva `.hero-word` y `.hero-person` = `public/papa_02.png`. **La foto y el recorte miden lo mismo (1088×1600)** y papá está en el mismo lugar en los dos, así que coinciden exacto. Si se cambia una, el recorte debe salir de esa misma foto.
  - **Las palabras:** `.hero-canco` y `.hero-star-word` (`.hero-line`) se ubican en % de la foto: `--canco-x/--canco-y` (-11 %, 25 %) y `--star-x/--star-y` (60 %, 59 %). Un `max()`/`min()` con `--lado` (espacio entre la foto y el borde de la pantalla, definido en `.hero`) evita que se salgan de la pantalla. `--letra` = `min(17cqw, (100vw - 32px) / 4.1)`: "CANCO" mide 4,0 veces la letra y "ST★R", 3,08 (medido; si cambias la fuente o la estrella, vuelve a medir y ajusta el 3.1 de `.hero-star-word`). `--star-y` está a la altura donde el delantal de papá tapa la parte de arriba de la "S", para que se note la profundidad. `line-height: 0.75` hace que la posición marque el borde de las mayúsculas.
  - **Accesibilidad:** las letras visibles van con `aria-hidden` y el `<h1>` tiene `<span class="visually-hidden">Canco Star</span>`, así que se lee "Canco Star" y no "ST R". La estrella (`.hero-star`, 0.92em de ancho y `margin-bottom: -0.05em` para centrarla con las mayúsculas) es `public/star_canco.png`: una copia con fondo transparente de `star_canco.jpg` (que tiene fondo blanco), recortada a la forma (488×425) y en el dorado original del logo (`rgb(196,160,41)`). Se generó con código: como la forma es de un solo color plano, la transparencia sale del canal azul. Si cambias el diseño de la estrella, entrégala en PNG transparente o en SVG.
  - **Animación:** cada letra es un `.hero-letter` con `--i` (su orden) y sube con un retraso de `0.25s + --i × 0.07s`: primero "CANCO" y después "STAR". La estrella entra girando (`hero-star-in`) y después hace un destello cada 4 s (`hero-star-shine`: crece un 8 %, gira 8° y brilla en dorado). Papá y las flores aparecen con un fundido. Todo se desactiva con `prefers-reduced-motion`.
  - **Encuadre:** `--hero-alto` (`clamp(480px, 100svh - 250px, 820px)`; en ≤768 px, `clamp(440px, 100svh - 340px, 700px)`) deja ver el subtítulo y el botón en la primera pantalla. `--foto-ancho` es como mínimo el que cubre ese alto y como máximo 1,3 × el alto: en computador la foto nítida es una columna central (sus bordes se desvanecen con una máscara del 16 %) y los lados son la misma foto muy desenfocada y oscura (`.hero::before`). `top` centra `--foco-y` (0,5, la zona de papá) sin dejar ver nunca un borde. `.hero-scene` se desvanece abajo y `.hero-text` (subtítulo y botón) sube 40 px sobre ese desvanecido.
  - **Flores a los lados** (`.hero-flor-izq`, abajo a la izquierda, y `.hero-flor-der`, arriba a la derecha y reflejada con `scale: -1 1`): las dos son `public/Flores_transparente.png`, en primer plano (`z-index: 4`), desenfocadas (`blur(4px)`) y oscurecidas (`brightness(0.58)`), para llenar los lados oscuros sin competir con papá. Su ancho sale del espacio libre a cada lado (`--lado`, × 1,25, entre 240 y 540 px), se meten un poco sobre el borde de la foto y llevan las mismas máscaras de cuatro bordes del recorte. Solo aparecen desde 900 px de ancho. Usan `rotate`/`scale` sueltos (no `transform`) para no chocar con la animación.
  - La cabecera de la tienda (`.tienda-hero`) conserva el degradado. Siguen en `public/`, pero no se usan en ningún lugar del sitio: `hero_flores.JPG`, `papá.png` y `Magic.png`.
- **Tarjetas de Legado y tradición** (`Cards.jsx`; sus textos y fotos están en `src/data/legado.js`): al hacer clic en cualquier parte de una tarjeta se abre una ventana ampliada con un `<dialog>` nativo (`showModal()`), que ya trae el foco atrapado, el cierre con Escape y el foco devuelto al cerrar. El botón "Leer más" se estira sobre toda la tarjeta con `.card-more::after`. Cada ítem de `cardsData` (en `data/legado.js`) tiene `detailImage`, `detailImageAlt` y `detail` (lista de párrafos). **Las fotos (`semilleros-cafe.png`, `campesinos.png`, `cabañas.png`, `campo.jpeg`) y los textos son temporales**, de ejemplo; están marcados con comentarios para reemplazarlos. La foto grande solo se descarga al abrir la ventana.
- **Around The World** (`components/AroundTheWorld.jsx`, ancla `#around-the-world`, después de Legado y tradición): usa el fondo general de la página. Tiene tres contadores (`AnimatedCounter.jsx`: un `IntersectionObserver` arranca la animación de 0 al número cuando el contador entra en pantalla, una sola vez), las pestañas Nacional/Internacional (`role="tab"`, que también se cambian con las flechas ← →), los filtros por región (solo en Internacional), un mosaico hecho con `columns` de CSS (3 columnas, 2 en celular y 1 por debajo de 380 px) y un visor de fotos en grande (`Lightbox.jsx`, con `<dialog>` nativo: flechas en pantalla y en el teclado, deslizar en celular, cierre con Esc o con clic en el fondo; navega solo entre las fotos visibles con el filtro actual).
  - **Datos:** `src/data/aroundTheWorld.js` tiene `fotos` (`imagen`, `ciudad`, `pais`, `bandera` como emoji, `categoria` "nacional" o "internacional", `region` y `frase` opcional), `regiones` (id, nombre y continente) y `alcance`. **`alcance` se calcula solo** a partir de `fotos`, al final del archivo: las ciudades distintas con `pais === "Colombia"`, los países distintos y los continentes (las nacionales cuentan como América; las internacionales toman el continente de su `region`). Una ciudad escrita de dos formas cuenta dos veces. Cualquiera de los tres valores se puede reemplazar por un número escrito a mano. Las fotos están en `public/Aroundtheworld/` (todas son JPEG, aunque varias terminan en `.png`). Las ciudades y las frases las escribe el equipo de Canco; no las inventes.
  - **Banderas:** Windows no dibuja los emojis de banderas. `main.jsx` llama a `polyfillCountryFlagEmojis` (paquete `country-flag-emoji-polyfill`), que carga la fuente `Twemoji Country Flags` solo cuando hace falta. La fuente va incluida en el build (no se descarga de un CDN) y está primera en el `font-family` del `body`; como solo contiene banderas, el resto del texto sigue en Segoe UI.
  - **Header con 5 enlaces:** entre 769 y 1000 px hay un `@media` provisional que achica el menú para que quepa. En celular el header ocupa 3 filas, por eso `--header-offset` es 190 px. Las dos cosas se pueden quitar con la Parte 3 (menú ☰).
- **Contenido editable:** las tarjetas salen del array `cardsData` en `data/legado.js`. `footer.jsx` tiene un comentario al inicio con instrucciones para editar redes y contacto.
- **Assets:** están en `public/` y se referencian con rutas absolutas (`/CANCO STAR.jpeg`, `/Reel-Canco.mp4`). Varios nombres tienen espacios o `ñ`. Los íconos de interfaz salen de `lucide-react` (por ejemplo, la flecha del menú); los de redes sociales son SVG inline.

- **Idiomas (español, inglés, portugués de Brasil y chino simplificado):** traducciones propias en `src/i18n/`, sin servicios externos.
  - **Archivos:** `es.js` (idioma base), `en.js`, `pt.js` y `zh.js`, con las mismas claves. `language.js` tiene la lista `idiomas`, el contexto y el hook `useLanguage()`. `LanguageProvider.jsx` guarda el idioma en `localStorage` (`canco-idioma`); en la primera visita usa el del navegador si es uno de los cuatro, si no, español. También actualiza `<html lang>`.
  - **Uso:** `const { t, idioma, setIdioma } = useLanguage()`. `t("menu.inicio")` da el texto de la interfaz y `t("carrito.quitar", { producto })` rellena los `{producto}`. Si a un idioma le falta una clave, se usa la del español.
  - **Contenido:** lo que vive en su propio archivo en español (`data/legado.js`, `data/productos.js`, `data/aroundTheWorld.js`) se traduce con `t.texto(textoEnEspañol)`, que lo busca **por el texto exacto en español** en la sección `textos` de cada idioma. Si no lo encuentra, muestra el original. Así, al cambiar un texto en español, los otros idiomas muestran el texto nuevo en español en vez de una traducción vieja; hay que agregar su traducción en `textos` de `en.js`, `pt.js` y `zh.js`. Los nombres de producto se guardan en el carrito en español y se traducen al mostrarlos. La búsqueda de la tienda busca en español y en el idioma elegido.
  - **Revisor:** `npm run traducciones` (`frontend/scripts/revisar-traducciones.mjs`) compara cada idioma con el español. Lista las claves de interfaz que faltan, los textos de contenido sin traducción (con el archivo donde está cada uno) y las traducciones viejas que sobran en `textos`. Por eso **el contenido debe vivir en `src/data/`**, que el script puede importar; si agregas otra fuente de contenido traducible, súmala ahí. Los nombres que se escriben igual en un idioma se registran en `textos` con el mismo valor (sección "lugares que se escriben igual"), o en `IGUALES` del script si son iguales en todos los idiomas. Úsalo después de cualquier cambio de texto.
  - **Regla:** todo texto visible nuevo (y los `aria-label` y `alt`) va en los cuatro diccionarios, no escrito directo en el componente. La marca ("CANCO", "CANCO STAR", "Around The World", "Castillo Tambo") no se traduce, y los precios siguen en pesos colombianos.
  - **Selector:** `components/LanguagePicker.jsx`, en `.header-actions` a la izquierda de la búsqueda. Es un globo (`Globe` de lucide) con el código del idioma y una lista hacia abajo (`.lang-menu`); se cierra al elegir, con clic afuera o con Escape. Cada opción lleva su propio `lang`.
- **Legado: reel + tarjetas** (`.legado-layout`): `contents.jsx` pasa el reel a `<Cards reel={<VideoReel />} />`. Es un grid: el reel en una columna a la izquierda (`minmax(240px, 340px)`, `position: sticky` bajo el header) y las tarjetas en 2 columnas a su derecha. Las dos primeras quedan al lado del reel y las otras dos debajo. En ≤1024 px el reel se angosta; en ≤768 px va arriba, centrado y sin sticky; en ≤560 px hay una tarjeta por fila. `#reel` sigue en el reel.
- **El menú abre la tarjeta:** los enlaces `/#procesos`, `/#familia`, `/#finca` y `/#paraiso` (menú, footer y el botón del hero) bajan a la tarjeta **y abren su ventana**. `Cards.jsx` lo calcula a partir de `useLocation()`: abre la tarjeta del hash salvo que esa navegación (`location.key`) ya se haya cerrado (`dismissedKey`). No usa un `setState` dentro de un efecto, por la regla de react-hooks. En la primera carga (`location.key === "default"`) no se abre, porque la página está detrás del splash.

- **Footer: ubicación:** `footer.jsx` tiene dos constantes arriba. `MAPA_ENLACE` es el link de Bing Maps a Acevedo; lo usan el texto "Acevedo, Huila - Colombia" y el mapa, y abre en una pestaña nueva. `MAPA_VISTA` es el iframe de OpenStreetMap (sin clave), con un `bbox` centrado en el pueblo. El mapa (`.footer-map`) es solo una vista previa: el iframe tiene `pointer-events: none` y es más grande que su marco (`top: -50px`, `left: -60px`), para recortar sus botones de zoom y su barra de créditos. Un enlace invisible (`.footer-map-link`) cubre todo el mapa y lleva a Bing. El filtro `invert + hue-rotate(180deg)` lo vuelve oscuro, y el pin dorado (`MapPin` de lucide) va en el centro. **Los créditos "© OpenStreetMap" son obligatorios por su licencia**: van en `.footer-map-credito`; no los quites.

## Backend

- **Estructura (Leaf MVC):** `public/index.php` es la entrada; `app/routes/index.php` registra `GET /api/users` y `POST /api/users`, que llaman a `app/controllers/UsersControllers.php`; `app/database/conexion.php` conecta con MySQL (`localhost`, `root`, contraseña vacía de XAMPP, base `canco`). `_auth.php` declara rutas `/auth/*` cuyos controladores no existen todavía.
- **Seguridad:** `GET /api/users` devuelve solo `COLUMNAS_PUBLICAS` (sin contraseña) y `POST /api/users` guarda la contraseña con `password_hash`. Para eso la columna `usuarios.contraseña` debe ser `VARCHAR(255)`: el cambio está en `backend/database/2026-10-25-contrasena-255.sql` y **se aplica a mano en phpMyAdmin** (no lo ejecutes tú). Las contraseñas que ya existen siguen sin encriptar.
- **No se suben a GitHub** (por `backend/.gitignore`): `.env` (tiene la `APP_KEY` real), `vendor/` (se instala con `composer install`) y `storage/logs`. **El repositorio es público**: nunca pongas una contraseña real en `conexion.php`; usa `.env`.
- La API no se publica en Vercel; necesita un hosting con PHP y MySQL. La tienda todavía no la usa (sus productos salen de `frontend/src/data/productos.js`).

## Despliegue

El sitio se despliega en Vercel desde la raíz del repositorio. Ten en cuenta dos cosas:
- `vercel.json` (en la raíz) le dice a Vercel que instale y compile dentro de `frontend/` (`installCommand`, `buildCommand`), que publique `frontend/dist` (`outputDirectory`) y que redirija todas las rutas a `/index.html`, porque `BrowserRouter` lo necesita para que entrar directo a una ruta o recargar la página no dé 404. No lo borres. Si algún día en Vercel se configura "Root Directory = frontend", este archivo tendría que ir dentro de `frontend/` y sin los `cd frontend`.
- `.vercel/` (datos del Vercel CLI) está en la raíz y en `.gitignore`. Antes estaba en `public/` y se publicaba con la página.
